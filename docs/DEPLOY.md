# Показ продукта без затрат

Три способа, все бесплатные. Ни один не требует ключей в репозитории.

## 1. Статическое демо (только просмотр) — GitHub Pages

Один HTML-файл: интерфейс + снимок ответов API для группы DEV (65 диалогов, оценки, чек-лист и его версии, шаблоны, апелляции, калибровка, инсайты, файл результатов). Сервер не нужен.

Собрать и открыть локально:

```bash
npm run build:static          # -> dist/static/index.html
```

Файл открывается двойным кликом (file://). Снимок строится из закоммиченных данных (`data/dev/DEV.json`, `data/seed/`, `config/checklist.v1.json`, `reports/calibration.json`) на временной базе; локальная `data/db` не используется и не меняется, модель не вызывается.

Что работает: все экраны, карточки диалогов, переключение версий, фильтры, переключатель языка RU/ҚАЗ/EN, экспорт CSV (из снимка), ссылка «Открыть запись» (исходная ссылка на звонок: аудиопрокси без сервера недоступен).
Что не работает: оценка, апелляции, решения, сохранение чек-листа, загрузка наборов — интерфейс показывает сообщение «демо только для просмотра» с подсказкой `npm start`. Внизу страницы постоянно видна плашка «Демо только для просмотра — полная версия: npm start».
Если в `data/seed` нет апелляций, экран «Апелляции» в демо пустой.

Публикация (делает владелец репозитория, один раз):

1. Сделать репозиторий публичным (Settings → General → Danger Zone → Change visibility). Pages для приватных репозиториев на бесплатном плане недоступны.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Actions → «Pages (static demo)» → **Run workflow** (запуск вручную, чтобы до включения Pages workflow не падал).

Workflow `.github/workflows/pages.yml` собирает демо на Node 24 и публикует `dist/static` только официальными действиями GitHub. Адрес: `https://<владелец>.github.io/<репозиторий>/`. До шагов 1–2 workflow завершится ошибкой — это ожидаемо.

## 2. Полный продукт на ноутбуке

```bash
npm start                     # http://localhost:8080
```

Нужен только Node 22.5+ (рекомендуется 24); npm-зависимостей нет, `npm install` не обязателен. Без ключей: в `.env` (скопировать из `.env.example`) указать `CQA_PROVIDER=offline` — оценки воспроизводятся из кэша `data/cache/eval`, затраты 0. База `data/db` создаётся при первом запуске из набора DEV и сохранённых оценок.

## 3. Render.com (необязательно)

Бесплатный web service по блюпринту `render.yaml`: Node 24, `npm start`, `CQA_PROVIDER=offline`, проверка `/api/health`.

1. Render → New → Blueprint → выбрать репозиторий → Apply (план Free).
2. Ключи провайдеров (если нужны) владелец задаёт только в панели Render: сервис → Environment. В репозиторий ключи не кладутся никогда.

Ограничения бесплатного инстанса: засыпает после простоя (первый запрос после сна — до минуты); диск временный — при каждом перезапуске база пересоздаётся из закоммиченных данных, новые оценки и апелляции теряются. Для показа жюри надёжнее варианты 1 и 2.

## 4. Живая система по ссылке на время защиты (Cloudflare quick tunnel)

Бесплатно, без аккаунта, ~1 минута: на ноутбуке с запущенным `npm start` выполнить

```bash
cloudflared tunnel --url http://localhost:8080
```

и отдать жюри адрес `https://….trycloudflare.com` из вывода. Ссылка живёт, пока открыто окно (Ctrl+C — закрыть).

**Только просмотр.** Запросы, пришедшие через туннель (заголовки Cloudflare `cf-connecting-ip` / `cf-ray`), не могут ничего изменить: оценка, апелляции, загрузка наборов и правка чек-листа отвечают 403 «Публичная ссылка открыта только для просмотра», а интерфейс показывает синюю плашку. Все изменения — на ноутбуке команды (`localhost`). Разрешить запись по ссылке осознанно можно переменной `CQA_PUBLIC_WRITE=1` (не рекомендуется: любой, у кого есть ссылка, сможет тратить квоту модели). Ключи модели остаются в `.env` на ноутбуке и через туннель не передаются.
