# Сценарий демонстрации (цель 4:30, жёсткий предел 5:00)

План организаторов: **1 мин** интерфейс и выбранный диалог · **2 мин** оценка, обоснование, переход к реплике, пример N/A, итоговый балл · **1 мин** апелляция → решение проверяющего → новый итог · **1 мин** изменение критерия и применение чек-листа. Один человек говорит, второй кликает. Шаги 1–3 полностью из сохранённых результатов (0 вызовов модели); единственный живой вызов — новый критерий в шаге 4, и для него есть вариант без модели.

Все числа ниже сверены с `results/dev/results.json` и `data/seed/DEV.evaluations.json` после переоценки DEV в ночь на 8 ноября (прогон `alem_qwen3-8_v6_rules`, эталон v1.1; в карточках «Оценено 08.11.2026, 02:28» по времени Астаны; `GET /api/conversations/:id`, `/api/stats`, `/api/calibration`) и пересчитаны общим движком `packages/scoring`. Если число на экране отличается от написанного — говорить то, что на экране.

## Перед началом (чек-лист драйвера)

- `npm start` → <http://localhost:8080>; `GET /api/health` → `"ok":true`, `counts.evaluations ≥ 65`.
- Шапка: роль **«Оператор»** (шаг 3 начинается от оператора), язык **RU**, масштаб браузера 125 %, окно 1366×768. Если зал большой и шрифт мелкий — кнопка **A+** в шапке (крупный шрифт для проектора, запоминается браузером).
- Закладки по порядку: `#/`, `#/c/p1-ru-006`, `#/c/p1-ru-003`, `#/c/p4-ru-003`, `#/c/p1-kz-013`, `#/c/p1-ru-015`, `#/appeals`, `#/checklist`, `#/calibration`.
- Апелляций нет (`/api/stats → disputes.total = 0`), иначе демо-апелляция будет не первой в очереди.
- Запись звонка `p4-ru-003` открыта один раз заранее (плеер `preload="none"` — первый клик идёт через прокси).
- Второй ноутбук с тем же репозиторием и папкой `data/`; резервное видео под рукой.
