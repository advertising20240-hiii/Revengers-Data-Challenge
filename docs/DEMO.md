# Сценарий демонстрации (цель 4:30, жёсткий предел 5:00)

План организаторов: **1 мин** интерфейс и выбранный диалог · **2 мин** оценка, обоснование, переход к реплике, пример N/A, итоговый балл · **1 мин** апелляция → решение проверяющего → новый итог · **1 мин** изменение критерия и применение чек-листа. Один человек говорит, второй кликает. Шаги 1–3 полностью из сохранённых результатов (кэш, 0 вызовов модели); единственный живой вызов модели — новый критерий в шаге 4, и для него есть вариант без модели.

Все числа ниже сняты с работающего приложения (`GET /api/conversations/:id`, `/api/stats`, `/api/calibration`) и пересчитаны общим движком `packages/scoring`. Если число на экране отличается от написанного — говорить то, что на экране.

## Перед началом (чек-лист драйвера)

- `npm start` → <http://localhost:8080>; `GET /api/health` → `"ok":true`, `counts.evaluations = 65`.
- Шапка: роль **«Оператор»** (шаг 3 начинается от оператора), масштаб браузера 125 %, окно 1366×768.
- Открыты вкладки-закладки в порядке: `#/`, `#/c/p1-ru-006`, `#/c/p1-ru-003`, `#/c/p1-ru-025`, `#/c/p4-ru-003`, `#/c/p1-ru-023`, `#/c/p1-kz-005`, `#/c/p1-ru-010`, `#/appeals`, `#/checklist`, `#/calibration`.
- Апелляций нет (`/api/stats → disputes.total = 0`), иначе демо-апелляция будет не первой в очереди.
- Запись звонка `p4-ru-003` открыта один раз заранее (плеер `preload="none"` — первый клик идёт через прокси).
- Второй ноутбук с тем же репозиторием и папкой `data/`; резервное видео под рукой.

## 3:40–4:20 · Изменение критерия и применение чек-листа (план: 1 мин)

Организаторы называют критерий на месте. Путь одинаковый для любого типа; ниже — с шаблоном, самый быстрый.

| # | Клик | Что на экране | Что говорим |
|---|---|---|---|
| 4.1 | `#/checklist` → в строке критерия (например, 07) → **«Заменить»** | модальное окно: шаблоны или «Пустой критерий» | «Контрольное задание — заменить критерий. Берём шаблон или описываем новый: текст, тип ответа, вес, условие N/A, подсказки модели — без кода» |
| 4.2 | выбрать шаблон (или заполнить новый) → критерий заменён, создана версия-черновик **v2** | diff: удалён / добавлен | «Старый критерий удалён, новый добавлен — в новой версии. Активная v1 не тронута» |
| 4.3 | **«Симуляция на N диалогах»** → выбрать 3–5 диалогов → **«Запустить симуляцию»** | результаты рядом с сохранёнными, пометка «Результаты симуляции не сохранены» | «Сначала симуляция — ничего не записывается, видим новый критерий и новые итоги рядом со старыми» |
| 4.4 | **«Сохранить и применить к выбранным»** → **«Сохранить, активировать и оценить»** | «Версия v2 применена»; в карточке строка **«кэш: 7 критериев, в модель: 1»** | «Применение: в модель уходит только новый критерий, остальные семь — из кэша. Результаты хранятся по версиям, переключатель версий — в карточке» |

**Если квота модели исчерпана** (баннер «Модель недоступна» или ошибка на 4.3): взять шаблон **«Скорость первой реакции»** — детерминированное правило `first_reaction` (Да/Нет, вес 5, порог 180 с; для наглядности поставить `threshold_seconds` = 90 — тогда часть диалогов получит «Нет», медиана первой реакции в DEV 75 с, p90 — 116 с). Правило не вызывает модель, симуляция и применение работают офлайн. Говорим: «Этот критерий — правило по фактам транскрипта, модель не нужна; LLM-критерий идёт тем же путём».

## Если что-то пошло не так

| Ситуация | Действие |
|---|---|
| Модель недоступна (баннер в шапке) | шаги 1–3 не зависят от модели; шаг 4 — шаблон «Скорость первой реакции» (правило) |
| Апелляция уже существует / очередь не пуста | открыть нужную по ID диалога в фильтре «Открытые»; числа те же |
| Аудио не играет | «Открыть запись» (ссылка на источник); подсветка строки #49 работает без звука |
| Сервер упал | второй ноутбук, `npm start` занимает секунды; данные те же (`data/`) |
| Проектор/ноутбук недоступны | резервное видео `pitch/assets/demo-backup.mp4` (вне репозитория), текст — `pitch/speaker-notes.md` |
