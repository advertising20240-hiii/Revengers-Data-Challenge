# Ограничения (честный список)

Что прототип не делает или делает с оговорками. Каждая цифра — из файла в `reports/`; методика — `docs/EVALUATION.md`, стоимость — `docs/COST.md`. Снимок на 2026-11-07 (вечер) после прогонов `reports/runs/alem_qwen3-8_v4_closure.json` и `alem_qwen3-8_v5_solo06.json`, эталон v1.1; первичны файлы отчёта.

## Оценка и её измерение

- **Цели точности §9.1 достигнуты не все.** На всех 65 (эталон v1.1): бинарные 01, 03, 05, 07, 08 — 95,4–100 % (цель ≥ 92 %); **02 — 89,2 %, ниже цели** (holdout 85 %): все 7 расхождений — граница «Нет» / N/A / «Да», самое спорное место чек-листа. Шкалы: 04 — 92,3 % точно / 96,9 % ±1 шаг, 06 — 84,6 % / 100 % (цель ≥ 70 / ≥ 90); грубые ошибки 8/8 без ложных. κ ≥ 0,61 на holdout не выполнено у 04 (0,50) и формально у 05 (0,608, ДИ [−0,07; 1]).
- **07 «Завершение» оценивается по буквальной формулировке чек-листа**: «Да» — только прощание **и** итог / следующий шаг / предложение дальнейшей помощи; вежливое «Пожалуйста. Хорошего дня!» после благодарности клиента — «Нет». Так мы прочитали чек-лист после ответа организаторов на прямой вопрос («Внимательно перечитайте чеклист по данному пункту»); эталон пересмотрен под это прочтение (v1.1, 31 диалог, причина в `tests/gold/dev_labels.json → revisions`, прежняя версия — `dev_labels.v1.0.json`). Правило и эталон следуют одной формулировке, поэтому 95,4 % по 07 — согласие с этим прочтением; если организаторы на контроле прочитают иначе, оценки 07 у вежливых прощаний разойдутся с их ожиданием. Список вежливых формул (`COURTESY_RE` в `services/evaluator/rules.js`) — RU/KZ/EN, проверен на DEV; новая формулировка прощания может потребовать дополнения списка.
- **06 исправлялось дважды после просмотра всех 65.** v3 — уточнение подсказки к ступеням; v5 — оценка 06 отдельным вызовом (в общем вызове на все критерии 70,8 %, отдельно — 84,6 %, holdout 75 → 95 %). Оба решения общие (ID диалогов никуда не вшиты), но приняты с учётом holdout, поэтому holdout по 06 уже не полностью «непросмотренный». Остаточная ошибка — соседние ступени (±1 шаг — 100 %).
- **Разброс модели между прогонами реален**: по 02 прогон v3 дал 95,4 %, v4 — 89,2 % при той же модели и том же шаблоне промпта (изменилась только строка 07 политики, из-за чего переоценены все критерии).
- **Первый отчёт содержал ошибочный вывод.** Цифры v1 «модель 16,9 % на 03, 46,2 % на 02» были в основном дефектом нашего валидатора (N/A модели читался как нарушение → 92 % диалогов в repair, 5 откатов к правилам). После исправления модель даёт на 03 95–98 %; маршрутизация перевыбрана, правила решают только 03 и 07. Файл `reports/runs/alem_qwen3-8.json` сохранён как история, а не как характеристика модели.
- **Выигрыш гибрида над моделью мал**: на всех 65 — два диалога по 07 и MAE итога 6,18 против 6,45; на holdout гибрид и модель совпадают (MAE 7,61). Ценность маршрутизации — детерминизм и независимость от квоты на 03/07, а не большой прирост точности.
- **Итоговый балл совпадает с эталоном точно в 53,8 % диалогов** (в пределах ±5 — 67,7 %, MAE 6,18): одна несовпавшая метка в 100-балльной формуле сдвигает итог на 5–20 баллов.
- **Эталон маленький, одиночный и командный.** `tests/gold/dev_labels.json` размечен участниками команды по чек-листу Freedom, а не организаторами: 65 диалогов (60 синтетических чатов + 5 реальных звонков; RU 35 / KZ 15 / EN 15), один разметчик, второго нет — межразметчиковая согласованность неизвестна. Holdout — 20 диалогов: 95 % ДИ шириной 15–30 п.п.; один диалог = 5 п.п. Любую цифру цитировать с интервалом (`criteria[].holdout.accuracy_ci`).
- **Маршрутизация выбиралась на этих же данных** (tune 45). Holdout — честная оценка, но распределение DEV ≠ реальные диалоги Freedom; при другом формате системных событий правило 03 нужно перемерять.
- **κ по шкалам 04/06 умеренная (0,59 / 0,49 на всех 65; holdout 0,50 / 0,69)** из-за парадокса распространённости: 72 % / 68 % эталонов на верхней ступени, p_e 0,59 / 0,49. Показываем p_e и матрицы ошибок рядом, κ не прячем.
- **Test–retest измерен на 20 диалогах** (96,9 % идентичных меток, `reports/runs/retest_injection.json`) — **на предыдущей версии политики**, до правки 07 и до отдельного вызова для 06; после этого не повторялся. На всех 65 и на контрольном наборе не повторялся (квота).
- **Проверка на инъекцию** — один синтетический случай с живой моделью (устойчив, та же предыдущая версия политики) и юнит-тест обрамления; систематического набора атак нет.
- **Проверяющая модель (`gpt-oss`) в измеренных прогонах выключена** (`--no-verify`): её вклад не измерен. В продукте включается только для результатов с уверенностью < 0,75.
- **Самооценка уверенности модели не калибрована.** Калиброваны (по tune) только уверенности 03/07 (`config/routing.json`). Порог 0,6 для очереди проверки выбран вручную.
- **Цикл обучения** — few-shot из решений проверяющего, не дообучение. Эффект не измерен (`learning_loop: null`); улучшения не заявляем. Ключ кэша не включает примеры — они действуют на новые диалоги или при принудительной переоценке.
- **Казахский.** Гибрид даёт KZ 95,8 % по всем меткам (15 диалогов, ДИ [90,6; 98,2]) и 100 % на holdout при 5 диалогах — выборка слишком мала для вывода «казахский не хуже». Казахское второе мнение (`kazllm`) в v4 и v5 расходилось с судьёй по 2 раза на 15 KZ-диалогов; кто прав при расхождении — не измерено.
- **Критерий 03** опирается на системное событие подтверждения личности и, для звонков, на устную идентификацию (ФИО/ИИН/адрес/SMS-код) в репликах — лексиконный сигнал, проверенный на 5 звонках DEV; другой контакт-центр потребует настройки лексикона.
- **Голос.** Транскрипты звонков — распознавание речи с ошибками; дикция, интонация, перебивания не оцениваются — аудио модели не передаётся.
- **Критерий 05 «Эмпатия»** оценивается по текстовым действиям; эмоции не выводятся.
- **Бесплатные провайдеры** имеют лимиты: у alem.plus лимит 200 запросов с неизвестным окном сброса; полная оценка 65 диалогов текущим продуктом (два вызова судьи на диалог) — ≈ 150–166 запросов. Продукт защищается кэшем, резервом 20 %, деградацией к правилам с честной подписью и офлайн-режимом, но живая демонстрация на незакэшированном диалоге может упереться в квоту.
- **Локальная модель (Ollama) не запускалась** — не установлена на машине разработки; качество на локальной модели не измерено.
- **Медиана задержки не сохраняется** в отчёте калибровки — только среднее (12,8 с на диалог для вызова по всем критериям + 3,5 с для отдельного вызова по 06); по-вызовные задержки есть в трассе каждой живой оценки.

## Продукт

- **Без аутентификации.** Роли «Оператор / Проверяющий» — переключатель интерфейса (разрешено условиями задания). Для продуктивного контура нужны роли безопасности (`docs/DYNAMICS365.md`).
- **Хранилище — JSON-файлы.** Достаточно для десятков тысяч оценок на одной машине; для нескольких серверов нужна БД или Dataverse.
- **Dynamics 365.** Собран один HTML-файл веб-ресурса и описано соответствие таблиц; решение Dataverse не развёрнуто, PCF-контрол не создан.
- **Экспорт** — CSV, печать карточки из браузера (кнопка «Печать», отдельные стили для печати) и файл результатов организаторов `results/dev/results.json` (JSON 1.0, `npm run export:results`, по активной версии чек-листа или `--checklist <версия>`); XLSX и PDF-отчёт не реализованы.
- **Интерфейс** — RU · ҚАЗ · EN с переключателем в шапке (`public/i18n/`). Названия критериев, секций и объяснения модели остаются на языке чек-листа (русском); цитаты-доказательства — на языке диалога.
- **Сервер по умолчанию слушает только `127.0.0.1`.** Чтобы открыть его в сети (контейнер за прокси), нужен явный `HOST=0.0.0.0` — и тогда аутентификация обязательна (`docs/SECURITY.md`).
- **Статическое демо** (`npm run build:static`, GitHub Pages) — только просмотр снимка DEV: оценка, апелляции, сохранение чек-листа и прослушивание записи через прокси в нём не работают (`docs/DEPLOY.md`).
- **Аудио** проксируется с `Range` только для `audio_url` загруженного диалога и только на публичные http(s)-адреса; если источник не отдаёт запись, предлагается открыть `audio_url` напрямую.
- **Загрузка набора по `group_id`** — только с адреса API организаторов из настроек сервера (`CQA_DATA_URL`); другой источник — через «Загрузить файл».
- **Шаблоны критериев** — 6; произвольные детерминированные правила (`rule:<name>`) требуют реализации в `services/evaluator/rules.js` — единственный случай, когда новый критерий требует кода.

## Данные

- DEV-набор синтетический (60 чатов) + 5 реальных звонков; поведение на реальных чатах Freedom не проверено.
- «Плохих» диалогов мало: по 04 всего 9 эталонов ≤ 10 баллов из 65, по 06 — 21 ниже верхней ступени; редкие классы измерены на единицах примеров.
