# Ограничения (честный список)

Что прототип не делает или делает с оговорками. Каждая цифра — из файла в `reports/`; подробности методики — `docs/EVALUATION.md`, стоимость — `docs/COST.md`.

## Оценка и её измерение

- **Модель ошибается, и мы знаем где.** `qwen3-8` одна даёт 15,4 % точности на критерии 03 и 46,2 % на 02 (`reports/calibration.json` → `comparison.splits.all.model`), поэтому эти критерии и 07 решают детерминированные правила, а модель — второе мнение. На смысловых критериях 04–06 модель лучше правил. Ниже цели §9.1 на всех 65 только 02 (89,2 % против ≥ 92 %; на holdout 95 %); шкала 06 проходит цели (75,4 % точно, 98,5 % в ±1 шаг) с минимальным запасом — на holdout ровно 70 % / 95 % при κ = 0,17.
- **Эталон маленький, одиночный и командный.** `tests/gold/dev_labels.json` размечен участниками команды по чек-листу Freedom, а не организаторами: 65 диалогов (60 синтетических чатов + 5 реальных звонков; RU 35 / KZ 15 / EN 15), один разметчик, второго нет — межразметчиковая согласованность неизвестна. Контрольная выборка — 20 диалогов: 95 % ДИ по критерию шириной 25–35 п.п.; один диалог = 5 п.п. Любую цифру цитировать вместе с интервалом (`criteria[].holdout.accuracy_ci`).
- **Маршрутизация выбиралась на этих же данных** (tune-часть, 45 диалогов). Holdout — честная оценка, но распределение DEV ≠ реальные диалоги Freedom; при другом формате системных событий правило 03 нужно перемерять.
- **κ по шкалам 04/06 низкая (0,42 / 0,23)** из-за парадокса распространённости: 72 % / 68 % эталонов стоят на верхней ступени. Мы показываем p_e и матрицы ошибок рядом, а не прячем κ.
- **Test–retest для модели не выполнен.** Повтор измерен только для правил (5 диалогов, 100 % — тривиально). Один прогон модели стоил 138 из 200 запросов квоты alem.plus; повторный прогон 20 диалогов на модели не проводился, цель «≥ 95 % идентичных меток» **не подтверждена**.
- **Проверка на инъекцию инструкций в транскрипт** выполнена только для правил (результат чистый). Для модели есть архитектурная защита (транскрипт в `untrusted`-блоке, строгая схема, валидатор, балл считает движок), но измерения нет.
- **Проверяющая модель (`gpt-oss`) в измеренных прогонах была выключена** (`--no-verify`, экономия квоты): её вклад в точность не измерен. В продукте она включается только для результатов с уверенностью < 0,75.
- **92 % судейских ответов не проходят валидатор с первого раза** и требуют повторного запроса (59 из 64, `alem_qwen3-8.json`). Это удваивает число вызовов и зависит от модели; после повтора 1 % результатов (5 из 512) уходит в консервативный ответ по правилам.
- **Самооценка уверенности модели не калибрована.** Калиброваны (по tune) только уверенности маршрутизированных критериев 02/03/07 (`config/routing.json`). Порог 0,6 для очереди проверки выбран вручную.
- **Цикл обучения** — few-shot из решений проверяющего, не дообучение. Эффект не измерен (`learning_loop: null`); ключ кэша не включает примеры, поэтому они действуют только на новые диалоги или при принудительной переоценке.
- **Казахский.** На модели одной KZ-диалоги хуже RU (67,5 % против 76,3 % на holdout); в гибриде разрыв исчезает (90 % против 93,8 %), но KZ — всего 15 диалогов (5 на holdout). Казахское второе мнение (`kazllm`) расходилось с судьёй в 9 из 15 диалогов — чаще сигнал к проверке, чем ошибка; кто из них прав, не измерено.
- **Голос.** Транскрипты звонков — распознавание речи с ошибками; дикция, интонация, перебивания не оцениваются — аудио модели не передаётся.
- **Критерий 05 «Эмпатия»** оценивается по текстовым действиям; эмоции не выводятся.
- **Критерий 03** опирается на системное событие подтверждения личности; если источник транскриптов его не пишет, нужна настройка лексикона или правила. Известная слабость — **голосовые звонки**: устная идентификация (ФИО, ИИН, код из SMS в репликах) событием не отмечена, и правило её не видит; сигнал устной идентификации добавляется в `rules.js` (без вызовов модели), после чего калибровка пересчитывается из кэша — цифры по 03 в `reports/calibration.*` первичны по отношению к этому тексту.
- **Проверка на инъекцию** — только обрамление и валидатор: юнит-тест с подставным провайдером (`tests/evaluator.test.js`) и прогон правил; с живой моделью не проводилась.
- **Детерминированность.** Правила детерминированы; модель при температуре 0 — высокая, но не стопроцентная повторяемость (не измерено, см. выше).
- **Бесплатные провайдеры** имеют лимиты: у alem.plus общая квота 200 запросов с неизвестным окном сброса. Продукт защищается кэшем, одним вызовом судьи, резервом 20 % и офлайн-режимом, но живая демонстрация на незакэшированном диалоге может упереться в квоту.
- **Локальная модель (Ollama) не запускалась** — на машине разработки не установлена; «качество на локальной модели» не измерено.

## Продукт

- **Без аутентификации.** Роли «Оператор / Проверяющий» — переключатель интерфейса (разрешено условиями задания). Для продуктивного контура нужны роли безопасности (`docs/DYNAMICS365.md`).
- **Хранилище — JSON-файлы.** Достаточно для десятков тысяч оценок на одной машине; для нескольких серверов нужна БД или Dataverse.
- **Dynamics 365.** Собран один HTML-файл веб-ресурса и описано соответствие таблиц; решение Dataverse не развёрнуто, PCF-контрол не создан.
- **Экспорт** — CSV; XLSX и печатная форма карточки не реализованы.
- **Интерфейс** — русский; строки KZ/EN подготовлены как i18n-файлы только если успели (см. `public/i18n/`).
- **Аудио** проксируется с `Range`; если источник не отдаёт запись, предлагается открыть `audio_url` напрямую.
- **Шаблоны критериев** — 6; произвольные детерминированные правила (`rule:<name>`) требуют реализации правила в `services/evaluator/rules.js` — единственный случай, когда новый критерий требует кода.
- **Медиана задержки не сохраняется** в отчёте калибровки — только среднее (21,8 с на диалог); по-вызовные задержки есть в трассе каждой живой оценки.

## Данные

- DEV-набор синтетический (60 чатов) + 5 реальных звонков; поведение на реальных чатах Freedom не проверено.
- «Плохих» диалогов мало: по критерию 04 всего 9 эталонов ≤ 10 баллов из 65, по 06 — 21 ниже верхней ступени; редкие классы измерены на единицах примеров.
- Пять пар «диалог × критерий» в кэше получены отдельным дооценочным запуском после основного прогона (откаты не кэшируются), поэтому столбец «только модель» в сравнении отличается от файла живого прогона на 1–2 диалога по критериям 03 и 07.

## Что в дорожной карте

Повторный прогон модели (test–retest) и проверка на инъекцию для модели при появлении квоты; второй разметчик и межразметчиковая κ; калибровка самооценки уверенности модели; измерение эффекта цикла обучения на отложенной выборке; распознавание речи для звонков (дикция); таблицы Dataverse и PCF-контрол; SLA апелляций; XLSX/PDF; KZ/EN интерфейс.
