# Ограничения (честный список)

Что прототип не делает или делает с оговорками. Каждая цифра — из файла в `reports/`; методика — `docs/EVALUATION.md`, стоимость — `docs/COST.md`. Снимок на 2026-11-07 после прогонов `reports/runs/alem_qwen3-8_v2.json` и `alem_qwen3-8_v3_c06.json`; первичны файлы отчёта.

## Оценка и её измерение

- **Цели точности §9.1 достигнуты на всех 65, но с оговорками.** Бинарные критерии 93,8–100 % (цель ≥ 92 %), шкалы 04 87,7 % точно / 96,9 % ±1 шаг и 06 83,1 % / 98,5 % (цель ≥ 70 / ≥ 90), грубые ошибки 8/8 без ложных. Не достигнуто: κ ≥ 0,61 на holdout у 06 (0,42, см. ниже) и test–retest для модели (не измерен).
- **06 «Ясность» исправлено формулировкой после просмотра всех 65.** В прогоне v2 было 67,7 % (модель мягче разметчика на 1–2 ступени); уточнение подсказки к ступеням по шкале организаторов и переоценка только 06 (`reports/runs/alem_qwen3-8_v3_c06.json`) дали 83,1 % / holdout 80 %. Формулировка — общая, ID диалогов никуда не вшиты, но подбиралась с учётом матрицы ошибок по всем 65 диалогам, поэтому holdout по 06 уже не полностью «непросмотренный». Остаточная ошибка — соседние ступени 4 ↔ 7 (8 из 20 «нижних» эталонов).
- **Первый отчёт содержал ошибочный вывод.** Цифры v1 «модель 16,9 % на 03, 46,2 % на 02» были в основном дефектом нашего валидатора (N/A модели читался как нарушение → 92 % диалогов в repair, 5 откатов к правилам). После исправления модель даёт 95,4 % на обоих; маршрутизация перевыбрана, правила решают только 03 и 07. Файл `reports/runs/alem_qwen3-8.json` сохранён как история, а не как характеристика модели.
- **Выигрыш гибрида над моделью мал**: на holdout один диалог по 03 и MAE итогового балла 4,9 против 5,8. Ценность маршрутизации — детерминизм и независимость от квоты на 03/07, а не большой прирост точности.
- **Эталон маленький, одиночный и командный.** `tests/gold/dev_labels.json` размечен участниками команды по чек-листу Freedom, а не организаторами: 65 диалогов (60 синтетических чатов + 5 реальных звонков; RU 35 / KZ 15 / EN 15), один разметчик, второго нет — межразметчиковая согласованность неизвестна. Holdout — 20 диалогов: 95 % ДИ шириной 25–40 п.п.; один диалог = 5 п.п. Любую цифру цитировать с интервалом (`criteria[].holdout.accuracy_ci`).
- **Маршрутизация выбиралась на этих же данных** (tune 45). Holdout — честная оценка, но распределение DEV ≠ реальные диалоги Freedom; при другом формате системных событий правило 03 нужно перемерять.
- **κ по шкалам 04/06 умеренная (0,50 / 0,42 на всех 65; holdout 0,72 / 0,42)** из-за парадокса распространённости: 72 % / 68 % эталонов на верхней ступени, p_e 0,57 / 0,50. Показываем p_e и матрицы ошибок рядом, κ не прячем.
- **Test–retest измерен на 20 диалогах** (96,9 % идентичных меток, `reports/runs/retest_injection.json`); на всех 65 и на контрольном наборе не повторялся (квота).
- **Проверка на инъекцию** — один синтетический случай с живой моделью (устойчив) и юнит-тест обрамления; систематического набора атак нет.
- **Проверяющая модель (`gpt-oss`) в измеренных прогонах выключена** (`--no-verify`): её вклад не измерен. В продукте включается только для результатов с уверенностью < 0,75.
- **Самооценка уверенности модели не калибрована.** Калиброваны (по tune) только уверенности 03/07 (`config/routing.json`). Порог 0,6 для очереди проверки выбран вручную.
- **Цикл обучения** — few-shot из решений проверяющего, не дообучение. Эффект не измерен (`learning_loop: null`); улучшения не заявляем. Ключ кэша не включает примеры — они действуют на новые диалоги или при принудительной переоценке.
- **Казахский.** На holdout гибрид даёт KZ 95 % при 5 диалогах (ДИ [83,5; 98,6]) — выборка слишком мала для вывода «казахский не хуже». Казахское второе мнение (`kazllm`) в v2 не расходилось с судьёй ни разу (в v1 — 9 раз, тоже следствие дефекта чтения ответов); кто прав при расхождении — не измерено.
- **Критерий 03** опирается на системное событие подтверждения личности и, для звонков, на устную идентификацию (ФИО/ИИН/адрес/SMS-код) в репликах — лексиконный сигнал, проверенный на 5 звонках DEV; другой контакт-центр потребует настройки лексикона.
- **Голос.** Транскрипты звонков — распознавание речи с ошибками; дикция, интонация, перебивания не оцениваются — аудио модели не передаётся.
- **Критерий 05 «Эмпатия»** оценивается по текстовым действиям; эмоции не выводятся.
- **Бесплатные провайдеры** имеют лимиты: у alem.plus общая квота 200 запросов с неизвестным окном сброса; полный прогон 65 диалогов — 82 запроса. Продукт защищается кэшем, одним вызовом судьи, резервом 20 %, деградацией к правилам и офлайн-режимом, но живая демонстрация на незакэшированном диалоге может упереться в квоту.
- **Локальная модель (Ollama) не запускалась** — не установлена на машине разработки; качество на локальной модели не измерено.
- **Медиана задержки не сохраняется** в отчёте калибровки — только среднее (17,0 с на диалог); по-вызовные задержки есть в трассе каждой живой оценки.

## Продукт

- **Без аутентификации.** Роли «Оператор / Проверяющий» — переключатель интерфейса (разрешено условиями задания). Для продуктивного контура нужны роли безопасности (`docs/DYNAMICS365.md`).
- **Хранилище — JSON-файлы.** Достаточно для десятков тысяч оценок на одной машине; для нескольких серверов нужна БД или Dataverse.
- **Dynamics 365.** Собран один HTML-файл веб-ресурса и описано соответствие таблиц; решение Dataverse не развёрнуто, PCF-контрол не создан.
- **Экспорт** — CSV и файл результатов организаторов `results/dev/results.json` (JSON 1.0, `npm run export:results`); XLSX и печатная форма карточки не реализованы.
- **Интерфейс** — русский; строки KZ/EN подготовлены как i18n-файлы только если успели (см. `public/i18n/`).
- **Аудио** проксируется с `Range`; если источник не отдаёт запись, предлагается открыть `audio_url` напрямую.
- **Шаблоны критериев** — 6; произвольные детерминированные правила (`rule:<name>`) требуют реализации в `services/evaluator/rules.js` — единственный случай, когда новый критерий требует кода.

## Данные

- DEV-набор синтетический (60 чатов) + 5 реальных звонков; поведение на реальных чатах Freedom не проверено.
- «Плохих» диалогов мало: по 04 всего 9 эталонов ≤ 10 баллов из 65, по 06 — 21 ниже верхней ступени; редкие классы измерены на единицах примеров.

## Что в дорожной карте

Граничные примеры для ступеней 4 ↔ 7 критерия 06; повторный прогон модели (test–retest) и инъекция с живой моделью при появлении квоты; второй разметчик и межразметчиковая κ; калибровка самооценки уверенности модели; измерение эффекта цикла обучения; распознавание речи для звонков (дикция); Dataverse и PCF-контрол; SLA апелляций; XLSX/PDF; KZ/EN интерфейс.
