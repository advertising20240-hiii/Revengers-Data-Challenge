# Ограничения (честный список)

Что прототип не делает или делает с оговорками. Обновляется по мере работы.

## Оценка

- **Модель ошибается.** Степень согласия с человеком измерена только на 65 DEV-диалогах (`reports/calibration.md`, когда отчёт сформирован); доверительные интервалы при таком объёме широкие, особенно по редким ответам (N/A для 04, «Нет» для 01). Цифры нужно читать вместе с интервалами.
- **Казахский.** Качество моделей на KZ ниже, чем на RU/EN. Смягчение — лексикон приветствий/представлений, казахское второе мнение (KazLLM через alem.plus, если настроен) и проверка каждого KZ-диалога калибровкой; гарантии нет.
- **Голос.** Транскрипты звонков — результат распознавания речи с ошибками; оцениваем содержание и просим модель игнорировать артефакты, но граница «артефакт / реальная ошибка оператора» субъективна. Дикция, интонация, перебивания не оцениваются — для этого нужен звук, а аудио модели не передаётся.
- **Критерий 05 «Эмпатия»** оценивается по текстовым действиям; прототип не выводит эмоции и не претендует на это.
- **Критерий 03** опирается на системное событие подтверждения личности; если источник транскриптов его не пишет (другой контакт-центр), нужна настройка лексикона или правила.
- **Детерминированность.** Температура 0 и фиксированная модель дают высокую, но не стопроцентную повторяемость; результаты теста «повтор» — в отчёте калибровки, не в обещаниях.
- **Цикл обучения** — few-shot из решений проверяющего, не дообучение. Эффект измеряется на отложенной выборке и может быть мал при малом числе решений.
- **Бесплатные провайдеры** (alem.plus, Ollama) могут иметь лимиты частоты и задержки; при недоступности система переходит на следующий провайдер или в офлайн-режим с кэшем. Измеренные задержки — `docs/COST.md`.

## Продукт

- **Без аутентификации.** Роли «Оператор / Проверяющий» — переключатель интерфейса (разрешено условиями задания). Для продуктивного контура нужны роли безопасности (`docs/DYNAMICS365.md`).
- **Хранилище — JSON-файлы.** Достаточно для десятков тысяч оценок на одной машине; для нескольких серверов нужна БД или Dataverse.
- **Dynamics 365.** Собран один HTML-файл веб-ресурса и описано соответствие таблиц; решение Dataverse не развёрнуто, PCF-контрол не создан.
- **Экспорт** — CSV; XLSX и печатная форма карточки не реализованы.
- **Интерфейс** — русский; строки KZ/EN подготовлены как i18n-файлы только если успели (см. `public/i18n/`).
- **Аудио** проксируется с `Range`; если источник не отдаёт запись, предлагается открыть `audio_url` напрямую.
- **Шаблоны критериев** — 6; произвольные детерминированные правила (`rule:<name>`) требуют реализации правила в `services/evaluator/rules.js` — это единственный случай, когда новый критерий требует кода.

## Данные

- DEV-набор синтетический (60 чатов) + 5 реальных звонков; поведение на реальных чатах Freedom не проверено.
- Человеческие метки — один набор без второго разметчика; меж-разметчиковая согласованность неизвестна, поэтому «согласие с человеком» означает согласие с этой разметкой.

## Что в дорожной карте

Распознавание речи для звонков (чтобы оценивать дикцию), развёртывание таблиц Dataverse и PCF-контрол, второй разметчик для калибровки, SLA апелляций, XLSX/PDF, KZ/EN интерфейс.
