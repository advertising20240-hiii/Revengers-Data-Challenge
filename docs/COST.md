# Стоимость и время оценки (COST)

Политика проекта — **нулевые затраты на вызовы моделей**. Каждая цифра ниже взята из файла в репозитории; имя файла указано рядом. Ничего не оценивается «на глаз». Там, где цифра — расчёт по прайс-листу, а не понесённый расход, это написано словом **ОЦЕНКА**.

## 1. Что измерено

Стоимость каждого вызова — **0 ₸**; токены и задержка записываются в трассу (`trace.calls[]`).

## 2. Квота и как продукт её бережёт

Заголовки ответа alem.plus показывали общий лимит **200 запросов** (читаются `readQuota()` в `services/evaluator/providers/alem.js`: `x-ratelimit-*-remaining/limit`); окно сброса **неизвестно**. Полный прогон 65 диалогов стоит теперь 82 запроса (было 138) — всё ещё **~40 % квоты**. Поэтому:

1. **Кэш по критерию** (`data/cache/eval/`, ключ = sha256(строки диалога, определение критерия, политика, версия промпта, модель)). Повторная оценка, пересчёт отчёта, новая версия чек-листа с неизменными критериями — 0 вызовов. Все 65 DEV-диалогов закэшированы и закоммичены.
2. **Один вызов судьи на диалог** (все 8 критериев в одном запросе; батчирование по 3 — только для локальных моделей ≤ 8B, `CQA_JUDGE_BATCH`).
3. **Валидатор и автоисправление без модели**; повторный запрос — максимум один, только по нарушенным критериям (после исправления — 3 % диалогов); дальше — консервативный ответ по правилам, а не третий вызов.
4. **Проверяющая модель только для неуверенных результатов**: для alem по умолчанию `CQA_VERIFY=low` — проверяются результаты с уверенностью < 0,75 (`CQA_VERIFY_THRESHOLD`).
5. **Резерв**: при остатке ≤ 20 % лимита (или `CQA_ALEM_RESERVE` запросов) судья автоматически переключается на резервную модель `fallback`; при 429 — пауза `retry-after` и переключение; при отказе провайдера — деградация к правилам с пометкой в `review_reasons`.
6. **Офлайн-режим** (`CQA_PROVIDER=offline`): воспроизведение из кэша; промах — явная ошибка, а не тихий вызов. Калибровка имеет флаг `--cache-only`, который отказывается стартовать, если потребовался бы хотя бы один живой вызов.
7. **Правила вместо модели там, где они точнее** (`config/routing.json`: 03, 07) — модель всё равно вызывается один раз на диалог, её ответ по этим критериям используется как второе мнение; правка правила не требует вызова.

## 3. Каскад (одна оценка = диалог × версия чек-листа)

1. **Факты** (0 вызовов): первая/последняя реплика оператора, событие подтверждения личности и устная идентификация в звонках, сигналы раскрытия/оскорбления/обхода, паузы, обрыв.
2. **Кэш** по критерию.
3. **Судья** — 1 вызов на диалог.
4. **Валидатор** (0 вызовов) → автоисправление → при оставшихся нарушениях один `repair` → консервативный ответ по фактам с уверенностью ≤ 0,5.
5. **Проверяющая модель** — только для неуверенных результатов; расхождение понижает уверенность и попадает в `review_reasons`.
6. **KZ-диалоги** — второе мнение `kazllm`, 1 вызов; расхождение понижает уверенность и попадает в `review_reasons`.
7. **Маршрутизация** (0 вызовов): 03 и 07 решают правила, модель — второе мнение; остальные шесть решает модель.

Измерено: **1,26 вызова на диалог** (82 / 65) при выключенной проверяющей модели; с ней — до ~2,3 (RU/EN) и ~3,3 (KZ).

## 5. ОЦЕНКА (не понесённые расходы): тот же объём токенов на платной модели

Формула — измеренные токены из `reports/runs/alem_qwen3-8_v2.json` × цены за 1M токенов из `services/evaluator/pricing.js` (цены записаны разработчиками; перед цитированием жюри сверить с действующим прайс-листом поставщика — дата сверки в репозитории не зафиксирована):

```
cost_run      = (T_in × P_in + T_out × P_out) / 1e6
cost_dialog   = cost_run / 65
cost_month(N) = cost_dialog × N
T_in = 437 863, T_out = 134 509  (судья + repair + kz, проверяющая модель выключена)
```

| Модель (прайс-лист `pricing.js`, $/1M вход / выход) | cost_run | cost_dialog | N = 50 000/мес | N = 100 000/мес |
|---|---|---|---|---|
| `claude-haiku-5-5` ($0,10 / $0,50) | $0,111 | $0,0017 | ≈ $85 | ≈ $171 |
| `claude-sonnet-5-5` ($2 / $10) | $2,22 | $0,034 | ≈ $1 708 | ≈ $3 417 |
| `claude-opus-5-5` ($4 / $20) | $4,44 | $0,068 | ≈ $3 417 | ≈ $6 833 |
| alem.plus `qwen3-8` (измерено) | **$0** | **$0** | **0 ₸** — ограничение не деньги, а квота запросов | |

До исправления валидатора та же оценка давала $0,0024 / $0,047 / $0,095 на диалог — исправление одного дефекта чтения ответа снизило бы счёт на платной модели на ~28 %. Не учтено: проверяющая модель (выключена; при `CQA_VERIFY=low` < 1 вызова на диалог ≈ 4k/0,5k токенов) и кэширование промпта у облачных провайдеров (системный промпт ≈ 3–4k токенов повторяется в каждом вызове — реальная цифра была бы **ниже**).

Пропускная способность на alem при `concurrency 3`: 370 с на 65 диалогов → ≈ 15 000 диалогов/сутки с одного процесса, если квота позволяет; реальный предел задаёт квота, а не время.

Единственный облачный вызов за всё время разработки: один тестовый запрос к `claude-haiku-5-5` для проверки формата ответа CLI (≈ $0,0004 по прайс-листу; результат не кэшировался).
