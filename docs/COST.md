# Стоимость оценки и выбор моделей (COST)

Политика проекта — **нулевые затраты на вызовы моделей**. Все измеренные цифры ниже получены скриптом `npm run calibrate` и записываются в `reports/calibration.json` (`cost`) и в трассу каждой оценки (`trace.calls[]`, `trace.cost_usd`, `trace.cost_note`). Ничего не оценивается «на глаз».

## 1. Что измерено на этой машине

| Конфигурация | Вызовов модели | USD | Время на диалог | Источник |
|---|---|---|---|---|
| `heuristic` — детерминированные правила по фактам транскрипта (без модели) | 0 | 0 | < 0.01 с | `reports/runs/heuristic_baseline_all.json`, 65 диалогов |

Поле `cost_note` в трассе для локальных/бесплатных провайдеров имеет вид «0 ₸ — локальная модель `<id>` на RTX 4050, ~N с на диалог» (секунды измерены) или «0 ₸ — детерминированные правила без модели».

Запуски с языковыми моделями (alem.plus, Ollama) появятся в этой таблице после первого разрешённого прогона `npm run calibrate -- --provider alem --split tune` — скрипт сам дописывает строку сравнения в `reports/calibration.md` (раздел «Сравнение моделей»).

## 2. Каскад и роли моделей

Схема одной оценки (диалог × версия чек-листа):

1. **Факты** (детерминированно, 0 вызовов): первая/последняя реплика оператора, событие подтверждения личности, сигналы раскрытия/оскорбления/обхода, паузы, обрыв связи. Для критериев с `evaluator: rule:*` это и есть окончательный ответ.
2. **Кэш** по критерию (`data/cache/eval/`, ключ = sha256(строки диалога, определение критерия, политика, версия промпта, модель)). Повторная оценка и применение новой версии чек-листа оплачиваются только за изменённые критерии.
3. **Судья** — 1 вызов на диалог (облачные/крупные модели) или 3 вызова по группам критериев (`CQA_JUDGE_BATCH=3`, локальные модели ≤ 8B, чтобы промпт укладывался в ~8k токенов).
4. **Валидатор** (0 вызовов) → при нарушениях **один повторный запрос** (`repair`) → иначе консервативный ответ по фактам с уверенностью ≤ 0.5.
5. **Проверяющая модель** другого семейства — 1 вызов; расхождение понижает уверенность и фиксируется в трассе (`verifier_changes`).
6. Для казахских диалогов — **второе мнение казахскоязычной модели** (роль `kz`), 1 вызов; расхождение → `kz_disagreements`, уверенность ниже 0.6 → «Требует проверки».
7. При 429/квоте/ошибке судьи — **резервная модель** (роль `fallback`) автоматически.

Итого на диалог: 2–3 вызова (RU/EN) или 3–4 (KZ) при одном вызове судьи; при пакетировании по 3 критерия — 5–6 вызовов.

## 3. Провайдеры

| Провайдер | Стоимость за вызов | Статус | Как включить |
|---|---|---|---|
| `alem` (alem.plus, Казахстан; OpenAI-совместимый API) | 0 ₸ (бесплатный доступ, токены и задержка записываются) | основной, если задан `ALEM_BASE_URL`+`ALEM_API_KEY`+`ALEM_MODEL_JUDGE` | роли `ALEM_MODEL_{JUDGE,VERIFIER,VERIFIER_ALT,KZ,FALLBACK}` с ключами/URL на роль (`ALEM_API_KEY_<ROLE>`, `ALEM_BASE_URL_<ROLE>`) |
| `openai` / `ollama` (локальная модель, `qwen2.5:7b` по умолчанию) | 0 ₸ (электричество; ~6 ГБ VRAM) | резерв; Ollama не установлен на машине разработки | `OPENAI_BASE_URL=http://localhost:11434/v1`, `OPENAI_MODEL=qwen2.5:7b` |
| `heuristic` | 0 | базовая линия и запасной вариант без модели | `CQA_PROVIDER=heuristic` |
| `offline` | 0 | воспроизведение из кэша; промах кэша — явная ошибка | `CQA_PROVIDER=offline` |
| `anthropic` (облако) | по прайс-листу | **заблокированы** политикой нулевых затрат | только `CQA_ALLOW_CLOUD=1` |

## 4. ОЦЕНКА (не понесённые расходы) для облачной модели — только для сравнения

Прайс-лист за 1M токенов: `claude-haiku-5-5` $0.10 вход / $0.50 выход; `claude-sonnet-5-5` $2 / $10; `claude-opus-5-5` $4 / $20 (чтение кэша $0.20 для Sonnet/Opus). Промпт судьи для одного диалога ≈ 4–6k токенов входа (чек-лист + политика + факты + транскрипт) и ≈ 1–1.5k выхода; проверяющая модель ≈ 4k / 0.5k.

Параметризованная формула месячной стоимости:

```
cost_month = N_dialogs × [ (T_in_judge × P_in + T_out_judge × P_out) + (T_in_ver × P_in_ver + T_out_ver × P_out_ver) ] × (1 + r_repair) / 1e6
```

где `N_dialogs` — диалогов в месяц, `T_*` — токены на вызов, `P_*` — цена за 1M, `r_repair` — доля повторных запросов (измеряется калибровкой, поле `cost.repairs`).

Пример подстановки (ОЦЕНКА, не измерение): N = 50 000 диалогов/мес, судья Sonnet (5k вход, 1.2k выход), проверяющий Haiku (4k вход, 0.5k выход), r_repair = 0.1 → 50 000 × [(5 000×2 + 1 200×10) + (4 000×0.1 + 500×0.5)] × 1.1 / 1e6 ≈ 50 000 × 0.0247 ≈ **$1 235/мес**. Полностью на Haiku ≈ $70/мес. На alem.plus или локальной модели — **0 ₸** за токены при тех же объёмах (ограничение — пропускная способность: при ~20 с на диалог один GPU даёт ≈ 4 300 диалогов в сутки).

Единственный облачный вызов, совершённый при разработке: один тестовый запрос к `claude-haiku-5-5` для проверки формата ответа CLI (≈ $0.0004 по прайс-листу, результат не сохранялся в кэш).

## 5. Решение

- По умолчанию: `alem` (судья — роль `JUDGE`; проверяющий — `VERIFIER`, иначе `VERIFIER_ALT`; KZ-диалоги дополнительно через `KZ`; резерв — `FALLBACK`). Стоимость 0 ₸; точность каждой роли измеряется отдельно: `npm run calibrate -- --provider alem --role judge|verifier|kz --split tune`.
- Без сети: `offline` (кэш для всех 65 DEV-диалогов лежит в `data/cache/eval/`) либо `heuristic`.
- Облако остаётся в коде как опция для сравнения и выключено.

## Summary (EN)

Zero-spend policy: every model call is free (alem.plus Kazakhstan-hosted API or a local Ollama model) or deterministic. Measured so far: heuristic baseline, 0 calls, 0 USD, < 0.01 s per dialog on 65 dialogs. Cloud providers are implemented but locked (`CQA_ALLOW_CLOUD=1`). The cloud figures above are list-price ESTIMATES for comparison only and were not incurred (one $0.0004 format-check call aside). Per-call tokens and latency are recorded in every evaluation trace; `npm run calibrate` aggregates them per model and role.
